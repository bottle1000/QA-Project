# QA 전달 자료

## 시작
터미널에서 다음을 실행합니다. 이 문서의 명령은 macOS용입니다.

```sh
cd /Users/bagbyeongcheon/Documents/Codex/2026-10-26/qa-qa-java-selenium-junit-jira-2/outputs/qa-practice
./start.sh
```

접속 주소: http://127.0.0.1:8087

시작은 소스를 빌드한 뒤 백그라운드에서 실행합니다. 브라우저나 터미널 창을 닫아도 서비스는 종료되지 않습니다. 이미 실행 중이면 중복 실행하지 않습니다. 초기 다운로드에는 인터넷이 필요하고 수 분이 걸릴 수 있습니다. 이후 다운로드한 의존성을 재사용합니다.

```sh
./status.sh
./stop.sh
```

서버 로그: 프로젝트 내부 `.run/server.log` (시작 시 새로 기록).
`./start.sh`는 실행 중인 서버를 재빌드하지 않으므로 수정 버전 실행은 종료 후 시작합니다.

## 계정
| 구분 | 아이디 | 비밀번호 | 표시 이름 |
|---|---|---|---|
| 일반 사용자 A | usera | Practice123! | 사용자 A |
| 일반 사용자 B | userb | Practice123! | 사용자 B |

초기 데이터는 각 회원의 게시글 2개씩, 총 4개입니다. 관리자 계정은 없습니다. 별도로 가입한 회원도 같은 일반 회원 권한을 갖습니다.

## 테스트 데이터 초기화
이 프로젝트에서 가입한 회원과 게시글을 모두 제거하고 기본 상태로 돌아갑니다. 다른 프로젝트의 데이터는 대상이 아닙니다.

```sh
./stop.sh
./reset.sh
./start.sh
```

실행 중에는 초기화를 거절합니다. 다음 시작 시 기본 계정과 게시글을 다시 생성합니다. 저장 위치는 이 폴더의 `data/qa.mv.db`입니다. 초기화하지 않으면 재시작 후에도 데이터가 유지됩니다. 초기화는 Git 버전이나 소스를 바꾸지 않습니다.


최초 상태를 현재 작업 파일과 별개로 다시 확인하려면 아래 명령을 사용합니다. 같은 이름의 폴더가 이미 있다면 다른 새 폴더 이름을 사용하세요.

```sh
./stop.sh
git worktree add --detach ../qa-practice-v0.1.0 practice-v0.1.0
cd ../qa-practice-v0.1.0
./start.sh
```

새 폴더의 데이터는 독립적이며 기본 상태로 시작합니다. 두 버전을 동시에 실행할 수 없습니다(동일 포트). 돌아오려면 새 폴더에서 `./stop.sh`를 실행한 후 원래 프로젝트에서 `./start.sh`를 실행합니다. 기존 수정본을 강제 덮어쓰는 명령은 필요하지 않습니다. GitHub 저장소: https://github.com/bottle1000/QA-Project
원격 저장소 이름은 `origin`입니다. 최초 버전 태그와 이후 수정 커밋을 함께 보존합니다.

## 환경 및 제약
- 확인 환경: macOS Apple Silicon, 설치된 Java 21, Python 3, Git, Google Chrome. 기본 셸의 Java는 25이나 관리 스크립트는 `/usr/libexec/java_home -v 21`로 Java 21을 선택합니다.
- Spring Boot 3.5.7, Maven 3.9.11, H2와 Thymeleaf는 프로젝트에 버전/의존성을 고정합니다. Maven은 `.tools/`, 의존성은 `.m2/`에 다운로드하며 전역 설정을 바꾸지 않습니다.
- 127.0.0.1:8087 전용이며 다른 기기에서는 접속할 수 없습니다. 8087 포트가 이미 사용 중이면 시작을 중단합니다.
- 단일 서버 프로세스용 파일 DB입니다. 별도 DB 서버나 Docker는 필요하지 않습니다. DB를 다른 도구로 동시에 열지 마세요.
- HTTP 로컬 실습용이며 실제 개인정보를 넣지 마세요. 운영 배포, 대량 부하, 메일, 외부 연동은 범위에 포함하지 않습니다.
- 같은 브라우저 프로필의 탭은 로그인 상태를 공유합니다. A/B 동시 사용은 다른 프로필 또는 시크릿 창을 사용하세요. 서버 재시작 후 로그인은 다시 해야 합니다.
- 날짜는 Asia/Seoul로 표시합니다. 표시 시각 정밀도는 초입니다.
- HTML form 기반 페이지 이동 방식입니다. 주요 입력과 버튼에 고정 id 및 label을 제공하며 오류는 role=alert, 성공 안내는 role=status입니다.
- Java Selenium/JUnit 학습용 별도 프로젝트, 테스트 코드, 테스트 케이스와 Jira 보고서는 포함하지 않습니다.
- ChromeDriver/Selenium은 서비스 실행에 필요하지 않으며 설치하지 않았습니다. 자동화 학습 단계에서 사용하는 브라우저 버전에 맞춰 준비하면 됩니다.

전달한 보고서의 정보로 재현 가능성을 먼저 확인합니다. 필요한 정보가 빠졌다면 구체적으로 요청합니다. 요구사항과 비교해 확인된 문제만 수정하고 별도 커밋과 버전을 안내합니다. 최종 재테스트와 Jira 종료는 QA 담당자가 수행합니다.

## IntelliJ IDEA에서 작업하기
1. IntelliJ에서 이 프로젝트 폴더를 Open으로 열고 Maven 프로젝트로 불러옵니다. 신뢰 확인이 표시되면 직접 만든 이 프로젝트를 신뢰하도록 선택합니다.
2. File → Project Structure → Project SDK를 설치된 Java 21로 선택합니다. Maven 동기화가 끝날 때까지 기다립니다.
3. 상단 실행 구성에서 `QA Practice`를 선택해 실행합니다. 구성이 보이지 않으면 `src/main/java/local/practice/Application.java`의 main 옆 실행 버튼을 누르고 작업 디렉터리를 프로젝트 루트로 지정합니다.
4. http://127.0.0.1:8087 에 접속합니다. 종료는 IntelliJ의 빨간 Stop 버튼을 사용합니다.

터미널로 실행한 서버가 있으면 먼저 `./stop.sh`로 종료하세요. IntelliJ 실행과 터미널 실행을 동시에 하지 않습니다. IntelliJ에서 실행한 서버는 IntelliJ에서 종료해야 합니다. 이후 프로젝트 터미널에서 `./reset.sh`를 실행하고 다시 Run하면 기본 데이터로 시작합니다. 실행 작업 디렉터리를 프로젝트 루트로 유지하면 터미널 실행과 같은 DB를 사용합니다.

IntelliJ는 Maven 의존성을 처음 불러올 때 별도로 다운로드할 수 있습니다. 이 IDE 설정 추가는 서비스 빌드 0.1.0의 기능이나 요구사항을 변경하지 않습니다.
