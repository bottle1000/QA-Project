# QA Practice 요구사항
문서 버전: 1.0 / 기준 빌드: 0.1.0 / 정책 확정일: 2026-10-26

이 문서는 모든 기능이 정상일 때의 판정 기준이다. 관찰된 구현에 맞춰 변경하지 않는다.

## 공통 정책
- COM-01: 로그인하지 않아도 목록과 상세를 볼 수 있다. 가입, 로그인, 로그아웃, 게시글 CRUD만 제공한다. 검색·페이지 나누기·첨부·이메일·결제·비밀번호 변경은 범위 밖이다.
- COM-02: 입력 길이는 Java 문자열 길이(UTF-16 코드 단위)로 계산한다. 아이디·표시 이름·제목·본문의 앞뒤 공백은 제거한 뒤 검사하고 저장한다. 비밀번호와 확인값은 공백을 제거하지 않는다. 본문 줄바꿈은 LF로 통일한다.
- COM-03: 오류는 화면의 role=alert 영역에 한국어로 표시하며 저장하지 않는다. 여러 오류가 있으면 아이디→비밀번호→확인→표시 이름, 제목→본문 순서로 첫 오류를 표시한다. 비밀번호는 오류 후 다시 입력한다. 나머지 입력은 유지한다.
- COM-04: 입력한 HTML은 실행하지 않고 문자로 표시한다. 새로고침과 서버 정상 재시작 후에도 회원·게시글이 보존된다. 로그인 세션은 서버 재시작 후 해제된다.
- COM-05: 시간은 Asia/Seoul 기준 초 단위로 표시한다. 게시글 ID는 고유 정수이며 삭제한 ID는 재사용하지 않는다(데이터 초기화는 예외).

## 회원과 인증
| ID | 정상 동작 및 판정 기준 |
|---|---|
| ACC-01 | 아이디는 영문 소문자 또는 숫자 4~20자. 위반 시 ‘아이디는 영문 소문자와 숫자 4~20자로 입력하세요.’ 표시. 대문자는 자동 변환하지 않는다. |
| ACC-02 | 이미 존재하는 아이디로 가입 불가. ‘이미 사용 중인 아이디입니다.’ 표시. |
| ACC-03 | 비밀번호는 ASCII 영문자와 숫자를 각각 1개 이상 포함한 8~32자이며 공백 불가. 특수문자는 허용. 위반 시 ‘비밀번호는 영문자와 숫자를 포함한 공백 없는 8~32자로 입력하세요.’ 표시. |
| ACC-04 | 비밀번호 확인은 비밀번호와 완전히 일치해야 한다. 다르면 ‘비밀번호 확인이 일치하지 않습니다.’ 표시하고 회원을 생성하지 않는다. |
| ACC-05 | 표시 이름은 공백 제거 후 2~20자, 중복 허용. 위반 시 ‘표시 이름은 2~20자로 입력하세요.’ 표시. |
| ACC-06 | 가입 성공 시 회원 1명 저장, 자동 로그인하지 않고 로그인 화면으로 이동해 ‘회원가입이 완료되었습니다.’ 표시. 비밀번호는 해시로 저장. |
| AUTH-01 | 저장된 아이디와 비밀번호가 일치하면 세션을 발급하고 목록으로 이동한다. 화면 상단에 표시 이름을 표시. 로그인 실패는 존재 여부와 관계없이 ‘아이디 또는 비밀번호를 확인하세요.’ 표시. |
| AUTH-02 | 로그아웃은 세션을 무효화하고 목록으로 이동한다. 이후 작성·수정·삭제 불가. 세션 유효 시간은 마지막 요청부터 30분. |
| AUTH-03 | 비로그인 상태의 작성·수정·삭제 접근은 로그인 화면으로 이동하며 ‘로그인이 필요합니다.’ 표시. 로그인 후에는 목록으로 이동한다. 로그인 상태에서 가입·로그인 화면 접근은 목록으로 이동. |

## 게시글
| ID | 정상 동작 및 판정 기준 |
|---|---|
| POST-01 | 목록은 모든 게시글을 ID 내림차순(최근 생성 우선)으로 표시한다. ID·제목·작성자 표시 이름·작성 시각을 표시. 없으면 ‘게시글이 없습니다.’ 표시. 제목 선택 시 해당 상세로 이동. |
| POST-02 | 상세는 ID·제목·본문·작성자·작성 시각·수정 시각을 표시. 최초 수정 시각은 작성 시각과 동일. 본문 줄바꿈 유지. 없는/삭제된 ID는 HTTP 404와 ‘게시글을 찾을 수 없습니다.’ 표시. |
| POST-03 | 로그인한 회원은 게시글 작성 가능. 제목은 공백 제거 후 1~100자. 위반 시 ‘제목은 1~100자로 입력하세요.’ 표시. |
| POST-04 | 본문은 공백 제거 후 1~2000자. 위반 시 ‘본문은 1~2000자로 입력하세요.’ 표시. |
| POST-05 | 작성 성공 시 제목·본문·로그인 회원의 작성자 ID·작성/수정 시각을 저장하고 새 상세로 이동. ‘게시글을 작성했습니다.’ 표시. |
| POST-06 | 작성자 본인만 수정·삭제 버튼을 볼 수 있다. 다른 회원이 URL 또는 요청으로 접근해도 HTTP 403과 ‘작성자만 변경할 수 있습니다.’ 표시하고 저장 데이터 유지. A와 B는 동일한 일반 회원 권한을 가진다. |
| POST-07 | 수정 화면에는 기존 제목·본문을 채운다. 작성과 동일한 입력 조건 적용. 성공 시 제목과 본문을 모두 갱신하고 수정 시각을 갱신하며 ID·작성자·작성 시각 유지. 상세로 이동하여 ‘게시글을 수정했습니다.’ 표시. 취소 시 저장 없이 상세로 이동. |
| POST-08 | 삭제 버튼은 브라우저 확인창 ‘게시글을 삭제할까요?’ 표시. 취소 시 유지. 확인 시 해당 게시글만 영구 삭제 후 목록으로 이동하고 ‘게시글을 삭제했습니다.’ 표시. |

## 실행과 데이터
- OPS-01: 서비스는 127.0.0.1:8087에만 바인딩한다. 다른 서비스 DB나 사용자 파일을 사용하지 않는다.
- OPS-02: 초기화는 서버 종료 상태에서만 수행하며 이 프로젝트 data/qa.mv.db 및 관련 H2 파일만 제거한다. 다음 시작 시 A·B 계정과 각각 2개씩 총 4개 게시글을 생성한다. 새로 가입한 계정 및 작성 글은 초기화 시 제거된다.
- OPS-03: 화면 하단의 빌드 식별자는 0.1.0이다. 최초 Git 태그는 practice-v0.1.0이다. 수정 시 별도 커밋과 버전으로 보존한다.
- OPS-04: 동일 브라우저 프로필의 탭은 세션을 공유한다. A/B 동시 검증은 다른 프로필 또는 시크릿 창을 사용한다. 같은 글 동시 편집은 마지막 저장을 적용한다.
